# nginx-updater

Один bash-скрипт, который приводит nginx на сервере в непростреленное состояние: находит все его установки, определяет, какие уязвимости реально открыты, обновляет, чинит конфигурацию и проверяет, что после этого сайты продолжают отвечать.

Написан под волну CVE, начавшуюся с **[CVE-2026-42945](https://nginx.org/en/security_advisories.html)** (NGINX Rift, CVSS 9.2, heap overflow в `ngx_http_rewrite_module`), но не привязан к ней: таблица уязвимостей подтягивается с nginx.org при каждом запуске.

[![Shellcheck](https://github.com/tagashi666/nginx-updater/actions/workflows/shellcheck.yml/badge.svg)](https://github.com/tagashi666/nginx-updater/actions/workflows/shellcheck.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

```bash
git clone https://github.com/tagashi666/nginx-updater.git
cd nginx-updater
sudo bash nginx-upgrade.sh --check    # посмотреть план
sudo bash nginx-upgrade.sh            # применить
```

Без зависимостей: только bash, coreutils и пакетный менеджер системы. `curl`, `gnupg` и `ss` доустанавливаются сами, если их нет.

## Зачем

Патчинг nginx выглядит просто ровно до того момента, когда им занимаешься всерьёз. Дальше выясняется:

- **Номер версии не говорит, уязвим ли сервер.** Debian, Ubuntu и RHEL бэкпортят фиксы, не меняя версию. `nginx 1.24.0` на Ubuntu 24.04 может быть полностью пропатчен — правда лежит в changelog пакета, а не в `nginx -v`.
- **Обновление умеет ломать сайты молча.** Переход на пакет nginx.org подменяет `nginx.conf` апстримовым, где нет `include sites-enabled` — все виртуальные хосты отваливаются, а `nginx -t` при этом рапортует «syntax is ok».
- **`systemctl is-active` ничего не доказывает.** nginx прекрасно бывает «active» с конфигурацией, не обслуживающей ни одного домена.
- **Одной версией дело не заканчивается.** Порог безопасности сдвигается с каждым новым адвизори, и захардкоженная в скрипте цифра устаревает через месяц.
- **nginx редко живёт в одном экземпляре.** Системный пакет, пара контейнеров из compose, чей-то `docker run` без compose, sidecar внутри чужого образа — и у каждого свой способ обновления.

Скрипт закрывает всё перечисленное за один запуск.

## Что он делает

### Определяет, уязвим ли сервер на самом деле

Вердикт выносится по пересечению двух условий: версия попадает в уязвимый диапазон **и** CVE не закрыт бэкпортом. Бэкпорты вычитываются из changelog установленного пакета — `changelog.Debian.gz`, `rpm -q --changelog`, `apk info -a`.

```
✓ системный nginx 1.24.0 (пакет 1.24.0-2ubuntu7.15) — уязвимости закрыты бэкпортами дистрибутива
```

Такой сервер не трогается вообще: ноль изменений, ноль риска.

**Отозванные патчи учитываются отдельно.** Дистрибутивы регулярно выкатывают фикс и следующей же ревизией отключают его — например, когда патч ломает ABI внешних модулей:

```
1.24.0-2ubuntu7.14   SECURITY UPDATE: ... CVE-2026-42533-1.patch
1.24.0-2ubuntu7.15   SECURITY REGRESSION: CVE-2026-42533-*.patch: Disabled for now.
```

Простой поиск CVE-ID по changelog прочитает вторую строку как «закрыто» — то есть ровно наоборот. Скрипт разбирает changelog по записям от новых к старым, распознаёт заголовок `SECURITY REGRESSION` и считает такой CVE открытым:

```
✗ CVE-2026-42533: дистрибутив ВЫПУСТИЛ и затем ОТОЗВАЛ патч
  → apt upgrade это не закроет — нужен nginx.org или исправленный патч от мейнтейнера
```

Обороты вида `disabled duplicate atoms in Mp4` (описание того, что делает патч) и `Dropped: ... replaced with upstream` (фикс приехал с новой версией) откатами не считаются.

Если changelog недоступен (docs вырезаны из образа), скрипт переходит на консервативную оценку по версии — считает уязвимым и предлагает обновление.

### Держит актуальный список уязвимостей

При запуске подтягивается и разбирается `nginx.org/en/security_advisories.html`, из него строится таблица «CVE → severity → уязвимые диапазоны → версии с фиксом». Целевая версия вычисляется из неё, а не берётся из константы. Нет сети — работает встроенный слепок на 23 CVE. Отключается флагом `--no-refresh`.

Записи, помеченные как Windows-only или `Vulnerable: all`, отбрасываются — они не про Linux-сервер.

### Обновляет по нарастающей

Сначала — репозиторий дистрибутива. Это безопасный путь: `nginx.conf` не подменяется, layout `sites-available`/`sites-enabled` остаётся на месте.

После обновления уязвимости пересчитываются заново. Если что-то осталось открытым и его серьёзность не ниже порога `--severity` (по умолчанию `major`) — тогда подключается репозиторий nginx.org.

Перед записью в `sources.list` пара «дистрибутив + кодовое имя» проверяется HTTP-запросом к `dists/<codename>/Release`. Для производных (Mint, Pop!_OS, Kali, Astra) есть маппинг на базовый Debian/Ubuntu. Несуществующий репозиторий не пропишется.

### Сохраняет конфигурацию при смене вендора пакета

Дерево `/etc/nginx` копируется в бэкап целиком. После установки пакета nginx.org файлы возвращаются через `cp -an` — новое от пакета не затирается, симлинки сохраняются.

Старый `nginx.conf` проверяется на совместимость с новым бинарником. Проходит `nginx -t` — остаётся. Не проходит — берётся апстримовый дефолт, в него переносятся `user`, `worker_processes` и include-и, а старый сохраняется рядом.

### Чинит конфигурацию

| Проблема | Действие |
|---|---|
| нет `include sites-enabled` / `conf.d` | вставляет в блок `http{}` |
| `user www-data;`, а пользователя нет | создаёт системного пользователя, раздаёт права на кеш-каталоги |
| `modules-enabled` тянет незагружаемый `.so` | отключает конкретный файл, на который ругнулся nginx |
| `listen 443 ssl http2;` (deprecated с 1.25.1) | переписывает на `http2 on;` |
| stock `conf.d/default.conf` от nginx.org перебивает ваш `default_server` | отключает |

Каждая правка проверяется `nginx -t` и откатывается поштучно, если не прошла. Миграция http2 применяется только в тех server-блоках, где **все** `listen` идут с `ssl` — иначе включился бы h2c на plaintext-порту.

Если после вставки include конфиг перестаёт проходить проверку, скрипт покажет настоящую ошибку из ваших сайтов, откатит вставку и пометит это как ручную работу — а не промолчит.

### Проверяет, что сервер продолжает работать

До изменений снимается слепок: какие сокеты слушает nginx и что отвечает по каждому из них. После — то же самое, и результаты сравниваются. Пропал сокет или порт перестал отвечать — конфигурация возвращается из бэкапа автоматически.

Полный `restart`, а не `reload`: фикс затрагивает разметку кучи в воркерах.

Если nginx не был запущен до прогона, скрипт ограничится `nginx -t` и не станет стартовать сервис за вас.

### Обновляет Docker

| Что нашлось | Что делает |
|---|---|
| compose с плавающим тегом | `pull` + `up -d` |
| compose с запиненным тегом `nginx:1.25.3-alpine` | поднимает до `1.30.4-alpine`, правит compose-файл и `.env` (с бэкапом) |
| образ собран локально | `compose build --pull` — иначе базовый слой возьмётся из кеша и пересоберётся та же дыра |
| контейнер из `docker run` без compose | пересоздаёт по слепку `docker inspect` |
| swarm-задача, `NetworkMode=container:*` | не трогает, помечает как ручную работу |
| OpenResty | распознаёт отдельно, не считает обычным nginx |

Пересоздание raw-контейнера: старый останавливается и переименовывается в `<имя>-preupgrade`, новый поднимается с воспроизведёнными портами, томами, сетями (с алиасами и статическими IP), переменными окружения, лейблами, capabilities, sysctl, ulimit, log-driver и restart policy. Не прошёл проверку — старый возвращается на место. Ничего не удаляется: `docker rm` вы делаете сами, когда убедились.

Версия nginx **внутри нового образа** проверяется до остановки контейнера — бессмысленного рестарта прода не будет.

### Замечает то, что не обновит

snap-пакет, сборка из исходников, ingress-nginx, остановленные контейнеры — детектируются и попадают в раздел «требуют ручной работы» с объяснением почему.

## Флаги

| Флаг | Что делает |
|---|---|
| `--check`, `--dry-run` | ничего не менять, показать план |
| `--json ФАЙЛ` | машиночитаемый отчёт |
| `--quiet` | тише, для cron |
| `--version` | версия скрипта |
| `--skip-system` / `--skip-docker` | не трогать системный nginx / контейнеры |
| `--distro-only` | никогда не подключать nginx.org |
| `--prefer-upstream` | сразу nginx.org, не пробуя дистрибутив |
| `--stable` / `--mainline` | ветка (по умолчанию stable) |
| `--severity LEVEL` | порог для миграции на nginx.org: `critical\|major\|medium\|low` (по умолчанию `major`) |
| `--no-fix-config` | не чинить конфигурацию |
| `--no-fix-http2` | не мигрировать `listen ... http2` |
| `--no-recreate` | не пересоздавать raw docker-контейнеры |
| `--no-rollback` | не откатываться автоматически при неудачной проверке |
| `--no-refresh` | не ходить на nginx.org за таблицей CVE |
| `--install-timer` / `--uninstall-timer` | systemd-таймер ежедневной проверки |
| `--webhook URL` | POST-нуть JSON-отчёт после прогона |

Переменная `NGXUP_WEBHOOK` — то же, что `--webhook`.

### Коды возврата

`0` — чисто · `1` — ошибка или осталось уязвимое · `2` — нужна ручная работа

## Флот

Все флаги рассчитаны на неинтерактивный запуск: ни одного вопроса, ни одного `read`.

```bash
mkdir -p logs reports
xargs -a hosts.txt -P8 -I{} sh -c '
  scp -q nginx-upgrade.sh root@{}:/tmp/ &&
  ssh root@{} "bash /tmp/nginx-upgrade.sh --check --quiet --json /tmp/r.json" > logs/{}.log 2>&1
  scp -q root@{}:/tmp/r.json reports/{}.json 2>/dev/null
  echo "{}: $?"
'

# кому реально нужно обновление
jq -r 'select(.system.open_cves|length>0) | "\(.host): \(.system.version) → \(.system.open_cves|join(", "))"' reports/*.json
```

Ansible:

```yaml
- hosts: web_servers
  become: true
  tasks:
    - name: nginx security upgrade
      script: nginx-upgrade.sh --quiet --json /tmp/nginx-updater.json
      register: r
      failed_when: r.rc == 1
      changed_when: r.rc == 0
```

Ежедневная автопроверка на одном хосте:

```bash
sudo bash nginx-upgrade.sh --install-timer
systemctl list-timers nginx-updater.timer
```

Таймер запускается раз в сутки с `RandomizedDelaySec=4h`, чтобы флот не пошёл на nginx.org одной толпой.

## Безопасность

До любых изменений в `/var/backups/nginx-updater/<timestamp>/` складывается: tarball `/etc/nginx`, распакованное дерево для восстановления, вывод `nginx -V`, список пакетов, слепок слушающих сокетов и дымовых ответов, `docker inspect` каждого контейнера.

`nginx -t` вызывается перед каждым рестартом и после каждой правки конфигурации. Всё логируется в `/var/log/nginx-upgrade/`.

Скрипт можно подключить как библиотеку — при `NGXUP_LIB_ONLY=1` он не делает ничего, только объявляет функции:

```bash
NGXUP_LIB_ONLY=1 source nginx-upgrade.sh
vuln_list 1.30.1        # какие CVE открыты в этой версии
target_version stable   # текущая безопасная версия
ver_ge 1.30.4 1.30.1    # сравнение версий
```

Это же используется в `tests/test-engine.sh` — 39 тестов движка версий, оценки уязвимости, порогов severity, распознавания отозванных патчей и разбора docker-тегов.

И всё же: обновление nginx — операция, которую не запускают вслепую на проде. Сначала `--check`, потом стенд, потом бой.
